# 可选子代理示例

这五份通用角色设定可按需导入，安装 TeamManeger 不会自动安装或覆盖它们。

在「设置 → TeamManeger → Subagent → 导入」中浏览本目录，预览并选择需要的角色后保存。导入前先检查已有同名角色及其自定义内容；如需替换，先备份并比较内容，再明确执行覆盖。批量导入会跳过已有同名角色。

| 角色 | 职责 |
| --- | --- |
| [Alice](alice.md) | 代码审查、需求核验、缺陷复现与验收 |
| [Kare](kare.md) | 视觉方向、美术资源、动效与动画 |
| [Limo](limo.md) | 需求澄清、架构、接口契约与任务拆分 |
| [Peter](peter.md) | 业务逻辑、服务接口、数据与系统集成 |
| [Tom](tom.md) | 页面组件、交互状态、接口与动画接入 |

示例刻意省略 `model` 和 `thinking`，沿用各自 DSH 环境的默认模型路由与思考等级；导入后可在角色编辑表单中按需指定。

派发任务时提供自包含说明：项目路径与工作目录、目标、必要上下文、需求与约束、允许修改的范围、输入输出及验收标准。角色正文可跨项目复用，每次任务的具体路径和要求放在派发提示中。

示例也省略 `deep` 与 `maxChildren`，解析后的实际默认值均为 **1**，可在表单中调整。`maxChildren` 的计数限制仅用于本插件的 `run_subagent` 派发；它不限制所有派生工具路径，执行还受宿主权限和深度预算约束。
